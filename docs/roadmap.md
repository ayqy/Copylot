# Copylot 商业 Roadmap v4.0

## 一句话结论

建议做低成本纠偏并列为组合第四优先级，因为 Copylot 尚无营收闭环，必须先删除不闭环问卷并退出新手引导/隐私风险主线，用无需引导的真实首次成功和复用决定是否值得建立最小付费结果。

## 当前单一承重约束

- 约束：可信的安装后首次成功与自然复用证据缺失。
- 依据：当前无营收闭环。；公开用户样本小且无评分。；本地事件不能外推全量。
- 置信度：`high`
- Fails if：Chrome Web Store、支持系统或可信 cohort 已提供用户级首次成功和复用数据。
- 最便宜反证：使用当前核心功能、官网简单说明和不采集正文的固定 cohort，验证新用户能否直接完成第一次干净复制并在自然周期复用。
- Kill criterion：目标用户多数无需该任务、无法直接成功或在自然周期不复用，则停止 Pro 与营收闭环建设并重新评估定位。

## SEO 与市场反馈规则

- `官网曝光增加但商店用户数不增加`：意图、承诺或安装承接不匹配 → 先修现有官网/商店表达；禁止推断：不得自动扩 SEO 页面
- `商店用户数增加但首次成功未知`：获客有变化但价值未验证 → 完成固定 cohort，不新增产品内引导；禁止推断：不得把安装当复用或收入
- `首次成功高但自然复用低`：任务频率或持续价值不足 → 审计真实工作故事和替代方案；禁止推断：不得进入 Pro
- `复用与真实付款同时出现`：出现商业入口 → 完成第二购买窗口后只产品化一个结果；禁止推断：不得从问卷或单笔付款扩套餐

- 每 7 天：数据健康与成功付款账单对账。
- 每 14 天：实验 Stop/Continue/Scale/Adjust。
- 每 30 天：按新证据重排路线。
- 每次发布：每次发布前冻结基线、动作与观察窗；窗口结束后由规则自动执行 Stop/Continue/Scale/Adjust。
- 触发式复审：官方商店用户数或评分变化；首次出现多个独立复用用户；第一笔真实成功付款；权限或正文处理方式发生变化

## 全局不做项

- 不把新手引导、Pro 问卷或隐私风险教育作为商业主线
- 不把 tracker、审计包、批准包、复核包或 handoff 当成果
- 不把本地处理自动解释为护城河或付费意愿
- 不在真实复用和购买结果前建设完整营收系统
