# Copylot 用户界面收敛与 Framer 整页复制无响应修复

## 背景

当前 Popup 同时展示快捷操作、第一次干净复制状态卡、首次成功后的复用卡和三步自动 onboarding，重复解释同一条路径并挤压真正的复制动作。Options 的隐私与 Pro 标签页虽然把部分内容放进折叠层，仍向普通用户暴露 telemetry、漏斗、campaign、evidence pack、validation lab、route verdict、stay_validation 等研发和运营过程信息。另有真实用户 badcase：在 Perplexity Research 的 Framer 文章页通过快捷键、Popup 或其他整页入口均无反应、无报错且剪贴板为空。真实浏览器复现表明内容脚本返回“没有可复制的内容”：页面用一个 `<header>` 包裹约 2.3 万字符的完整文章，而当前阅读模式清洗会无条件删除所有 `<header>`；各入口随后又忽略了失败响应，最终表现为静默失败。

## 目标

把 Copylot 的 Popup 收敛为打开即可复制的工具面板，把 Options 的隐私与 Pro 页面重构为普通用户能快速理解和信任的产品界面；同时修复 Framer 等非标准语义页面的整页提取，确保 Popup、快捷键与右键等入口对成功和失败都有明确反馈，并让指定 Perplexity Research 页面稳定生成非空、可用的 Markdown。

## 结合项目代码的需求澄清

1. Popup 由 `src/popup/popup.html`、`src/popup/popup.css`、`src/popup/popup.ts` 与中英文 locale 驱动。当前 `first-copy-*`、`reuse-primary-*`、`popup-onboarding-*`、`wom-status-hint` 及 `renderFirstCopySummary()`、`openOnboardingModal()`、`completeOnboarding()`、`syncWomActionAvailability()` 等共同形成了过度引导和基于内部增长状态切换主动作的体验；`runQuickAction()` 对普通复制不等待 `chrome.tabs.sendMessage()`，并在未确认结果前关闭 Popup。
2. Options 由 `src/options/options.html`、`src/options/options.css`、`src/options/options.ts` 驱动。隐私页的事件日志、Pro 漏斗、增长统计、追加状态和 JSON/CSV 导出，以及 Pro 页的路线验证、campaign、分发包、决策包、verdict、收费审计等 DOM 和事件绑定均是内部工具，不应继续出现在普通用户界面。共享 `src/shared/pro-*` 模块和独立证据脚本仍可保留给内部离线流程，本轮只移除其 Options 用户界面、专属绑定和无用 import，不扩张为商业化重构。
3. `src/shared/settings-manager.ts` 当前把 `isAnonymousUsageDataEnabled` 默认设为 `true`，而 `docs/privacy-policy.md` 明确写为默认关闭。为了让隐私页面陈述与真实行为一致，新安装默认值应改为 `false`；已有明确存储的用户选择保持不变。界面应使用“本地使用记录”这类用户语言，明确记录仅保存在当前设备、不含网页正文、标题和 URL、不会联网发送，关闭后清除对应本地事件日志。
4. 指定 badcase 的共同提取链为 `src/content/content.ts` 的整页消息处理 -> `src/shared/content-processor.ts` 的 `processContent()` / `prepareReaderModeRoot()` -> `src/shared/dom-preprocessor.ts` 的 `stripReaderModeNoise()` / `shouldStripReaderModeNoiseNode()`。真实页面没有 `main` 或 `article`，密度选择落到 `#main`，完整正文位于 `header.framer-159wj77`；`READER_MODE_STRUCTURAL_NOISE_TAGS` 无条件包含 `header`，因此正文被删除。修复应只保留低链接密度、拥有足够正文和段落信号的内容型 header，普通导航 header、nav、aside、footer 等噪声仍需过滤。
5. 全入口链路还包括 `src/background.ts` 的 `handleConvertPageContextMenu()`、`handleContextMenuClick()`、`executeQuickActionCommand()` 与 `chrome.commands.onCommand`。这些函数需要传递统一的成功/失败结果；内容脚本需在页面上提供本地化、可访问的成功/错误状态提示，Popup 则在等待期间显示进行中状态、仅在成功后关闭，失败时保留窗口并给出恢复建议。
6. 现有自动化覆盖普通 article、semantic main、density fallback 和噪声裁剪，但没有“完整正文被非标准 header 包裹”的回归样本，也没有验证 Popup 对失败响应的处理。需要在 `test/fixtures/content/`、`scripts/content-interaction-tests.ts`、`e2e/fixtures/` 与相关 Popup/commands/context-menu/options E2E 中补齐代表性 Framer 结构、全入口结果反馈以及用户化 UI 断言。指定线上 URL不应成为持续集成的强网络依赖，但执行验收必须用当时抓取的真实页面在临时目录中回归。

## 具体任务

1. 收敛 Popup 信息层级与交互：删除第一次干净复制状态卡、首次成功复用卡、自动 onboarding、Options 内的新手引导入口和基于成功次数锁定分享/评价的提示；固定“复制选中内容或整页”为稳定主动作，把已配置 Prompt 快捷位作为并列的次级快捷动作，把追加收集状态移到快捷操作附近且仅在有会话时显示；保留基础开关、更多设置、快捷键、Prompt 管理、反馈、分享、评价和 Pro 规划入口，但将“升级 Pro”改为不暗示已上线的用户文案。
2. 为 Popup 主动作补齐状态模型：新增进行中、成功、无内容、当前页不可用、剪贴板失败等本地化反馈；主按钮等待真实响应，成功后关闭 Popup，失败时恢复可操作状态并保留包含下一步建议的 `aria-live` 提示；快捷键和右键入口由内容页提示确认结果，不再静默失败。
3. 重做 Options 隐私页：把页面标题、说明和数据边界改为普通用户语言，按“复制内容如何处理”“设置与 Prompt 保存在哪里”“本地使用记录由你控制”的决策顺序组织；提供语义正确的本地记录开关、即时状态、关闭即清除说明和完整隐私政策入口；从用户 DOM 与初始化流程移除事件 JSON、Pro 漏斗、增长/口碑/追加统计、证据包及各种导出面板，并将新安装的本地使用记录默认改为关闭。
4. 重做 Options Pro 页：明确显示“规划中 / 尚未上线”，用用户场景说明免费版当前能力和正在探索的复杂页面清理、多页面收集、工作流导出方向；保留一个“查看 Pro 规划”主动作和必要的状态/边界说明，明确当前没有订阅、付费或候补名单且免费功能不受影响；删除 validation lab、S3 编号、campaign、distribution、route comparison/writeback/stability/verdict、payment audit、messaging guard、内部证据导出、GitHub 源码范围文档和不属于 Pro 判断任务的口碑操作卡，同时清理 `options.ts` 中只服务这些 DOM 的绑定与 import。
5. 同步 Options 全局身份与双语文案：把页面头部从仅代表 Prompt 管理器的标题改为 Copylot 设置语义，把标签命名统一为 Prompt、AI 服务、隐私与数据、Pro 规划；同步 `_locales/zh/messages.json` 与 `_locales/en/messages.json` 中所有仍在活跃界面使用的标题、按钮、帮助、状态、成功和错误文案，保证术语稳定、短句直接、英文扩展时不撑裂布局。
6. 修复 Framer 整页提取：调整 `src/shared/dom-preprocessor.ts` 的结构噪声判定，为低链接密度、正文长度和段落结构达到门槛的内容型 header 提供保留规则，同时继续删除普通页头、导航、侧栏、页脚、分享和推荐噪声；复核 `processContent()` 对目标结构返回非空 Markdown，并确保标题、正文段落、列表和代码等内容保留。
7. 统一复制请求结果与页面反馈：在 `src/content/content.ts` 抽取整页/选区复制的共用处理函数和明确的响应类型，确保无内容、设置不可用、剪贴板失败和成功都返回可判定结果并显示不遮挡正文的本地化状态提示；在 `src/background.ts` 与 Popup 中完整等待并透传结果，避免把 `{ success: false }` 当作已执行完成。
8. 补齐回归测试：新增最小 Framer header 文章 fixture，覆盖正文保留与导航噪声删除；更新内容交互、快捷键、Popup、右键整页入口测试，断言非空 Markdown、真实剪贴板结果、成功计数和错误反馈；重写受影响的 Popup 布局/设置与 Options 隐私/Pro E2E，断言第一屏主动作稳定、内部术语和内部工具不再出现在用户 DOM、隐私默认值与政策一致、Pro 不暗示已上线；同步静态 UI 集成断言与 i18n 检查。
9. 按 `ui` skill 的维护模式完成视觉验收：使用真实扩展运行态分别截取中文 Popup、Options 隐私、Options Pro 的主截图，并补查英文、窄宽度和深色模式；逐张检查主任务层级、返回用户的状态、间距节奏、文案换行、焦点与对比度、卡片嵌套、内部流程感和滚动溢出。发现任何明显体验问题时继续修改、重新构建、重新截图和复核，直到所有 UI review gates 通过。
